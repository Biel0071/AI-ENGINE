# FÊNIX Ω∞ — PROJECT PLUGIN SPECIFICATION

> **Especificação do Sistema de Plugins de Projetos Conectados**

---

## 📁 Estrutura Padronizada por Projeto Federado

Cada repositório ou aplicação conectada ao FÊNIX Ω∞ DEVE manter a seguinte estrutura de diretórios e arquivos de inteligência:

```
<project_root>/
├── manifest.json            # Metadados e identificação do projeto
├── project_dna.json         # Genoma completo de software (Stack, DDD, Ports)
├── engineering_score.json   # Engineering DNA Score (0 a 100 em 10 dimensões)
├── knowledge_graph/         # Grafo de conhecimento específico do projeto
├── digital_twin/            # Modelo computacional dos 11 Espelhos
├── capsule/                 # Histórico de cápsulas locais do projeto
├── logs/                    # Audit logs de execução e interações do enxame
├── benchmarks/              # Medições de latência, CPU, memória e tokens
├── playbooks/               # Manuais de execução autônoma gerados
└── capabilities/            # Capabilities exportadas para o mercado interno
```

---

## 🔄 Protocolo de Ingestão em 20 Etapas

Ao conectar qualquer projeto, o FÊNIX executa automaticamente:
1. Inventário de Arquivos
2. Análise AST (Abstract Syntax Tree)
3. Mapeamento de Dependências
4. Espelho Arquitetural
5. Espelho de Banco de Dados (Schemas & RLS)
6. Espelho de APIs (REST / OpenAPI)
7. Análise de Containers Docker & Compose
8. Análise de Pipelines CI/CD
9. Análise do Frontend (Componentes UI & Design Genome)
10. Análise do Backend (Services, Controllers & Workers)
11. Auditoria de Segurança OWASP
12. Profiling de Performance
13. Mapeamento de Observabilidade
14. Análise de Cobertura de Testes
15. Auditoria de Documentação
16. Construção do Knowledge Graph Específico
17. Sincronização do Digital Twin (11 Espelhos)
18. Cálculo do Engineering DNA Score (0 a 100)
19. Geração de Backlog Técnico Priorizado
20. Capability Matching no Catálogo Global
