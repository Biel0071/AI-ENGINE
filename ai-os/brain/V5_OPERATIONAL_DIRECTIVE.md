# FÊNIX Ω∞ V5 — LIVING ENGINEERING PLATFORM DIRECTIVE

> **Diretriz Operacional do Sistema Operacional de Engenharia V5**

---

## 1. Regra Nº 1 (Engenharia Mediada por FÊNIX)

A partir da versão V5, nenhuma funcionalidade ou refatoração é desenvolvida manualmente.
Toda e qualquer alteração de código ou infraestrutura DEVE passar obrigatoriamente pelo fluxo autônomo do FÊNIX Ω∞:

```
Prompt de Intenção ──► Mission Compiler ──► Agent Swarm ──► Digital Twin ──► Shadow Runtime ──► Quality Gate (272 Testes) ──► Staging ──► Memory Council ──► Capsule Ω
```

---

## 2. O Conselho de Memória (Memory Council)

Para evitar a "poluição cognitiva", nenhum aprendizado ou capability vira patrimônio permanente sem ser aprovado pelo **Memory Council** através de 5 portões de validação:

```
Research Gate ──► Evidence Gate ──► Confidence Gate ──► Security Gate ──► Architecture Gate ──► Persistência na Capsule Ω
```

---

## 3. Shadow Runtime (Execução em Sombra)

Toda proposta de refatoração ou melhoria roda primeiro no **Shadow Runtime** (um clone efêmero e isolado da aplicação):
1. O Shadow Runtime executa a alteração.
2. Compara latência, uso de memória, consumo de CPU e taxa de erro em relação ao baseline.
3. Se e somente se as métricas forem estritamente superiores ao baseline, a alteração é promovida para Staging.
