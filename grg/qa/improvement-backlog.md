# Fênix OS — lista contínua de melhorias

Este backlog é a lista de trabalho mantida no repositório para evolução visual e operacional do Fênix. A fila de QA gerada em `qa-results/` continua sendo um relatório automático; ela não substitui esta lista.

## Evidência das capturas e do runtime

- As capturas enviadas mostram a Cidade com área vazia ao redor de uma ilha pequena, escala e perspectiva difíceis de controlar, edifícios repetitivos e controles pouco explicados.
- As capturas mais recentes mostram dois minimapas com a mesma imagem estática, o feed de alertas sem leitura da API e “snapshot Event” repetido na faixa inferior. O rodapé também exibe o host do navegador (`localhost:8890`) como se fosse o host do sistema e mantém um selo verde mesmo sem telemetria.
- O aviso `HTTP 404` do chat visto em `http://localhost:8890` veio do preview estático, que não hospeda o backend. Ele não comprova sozinho uma falha na API pública.
- Na API pública, a rota de sessão do Provider Platform ainda não existe no backend implantado. O chat autenticado da API Platform retornou `500` porque a cadeia de provedores falhou; uma inferência local do Ollama também excedeu o timeout observado. Esses são bloqueios distintos do `404` do preview.
- As métricas vazias do preview (`CPU`, `RAM`, `uptime` e providers) são “sem leitura”, não valores zero ou disponibilidade confirmada.
- Validação somente de leitura em 13/10/2026: a API pública respondeu `200` em `/api/v2/system/health` com `ONLINE`, CPU `100`, RAM usada `4272/5921 MB` e uptime `22661 s`; esses campos são compatíveis com os medidores do rodapé. `/api/v2/events/history` retornou `401` sem sessão, então o feed de eventos exige a sessão autenticada do Fênix.

## Fatia implementada neste ciclo

- Renderer: `grg/public/fenix-world-3d.js` e estilo do canvas em `grg/public/fenix-world-3d.css`.
- Testes: `grg/test/city-world3d-pointer-ownership.test.js` e `grg/test/city-world3d-terrain.test.js`.
- Verificação local: sintaxe JavaScript e testes focados passaram. Esta fatia ainda não foi implantada nem validada na VPS.
- Esta atualização local acrescenta interpolação de coordenadas, fallback determinístico de agentes, minimapa único baseado no mundo real e estados de eventos/telemetria derivados de API/SSE. Os painéis de Operações/Cockpit e o atalho do mascote também deixaram de afirmar `ONLINE`, `STANDBY` ou incidentes zero sem medição. A fonte atual `/api/v2/events/history` usa o histórico do event bus do processo; retenção durável após restart ainda precisa ser implementada/validada no backend.
- Os envelopes de erro da API deixaram de ser contados como entidades (a causa do falso “1 missão”). Os KPIs do topo agora contam agentes explicitamente online e missões em execução; a lista inferior segue mostrando quantidades totais quando a leitura funciona. A lista de eventos também filtra snapshot, status e heartbeat antes de alimentar rodapé/modal; o sino só exibe alertas críticos/avisos recebidos da API. Removi clima/horário fixos e atualizei as versões dos scripts para invalidar cache no navegador.
